# M10: common correction scales by requantizing existing INT8 planes

P33 keeps current K128 quantizers and combines integer accumulation only when all four restoration exponents already agree. This passes the matrix gate, but independent full calls remain about37us versus productionSW about10us. P34 disabling paired common paths regressed about0.9percent. This motivates a distinct numerical algorithm, not another scheduling-only control.

M9 directly quantized the original high/residual FP32 values overK512. M10 instead starts from the current four quantizedK128 slabs. For each existing A64-row or B32-column quantizer tile and each INT8 plane, choose the maximum of its four stored exponents, E=max(e0..e3), then set q'_k=RN(q_k*2^(e_k-E)). The ratio is a power of two <=1, the signed result stays within[-127,127], and all four metadata entries repeatE. Relative low/high exponent spacing remains11(FP16)/8(BF16) for transformed pairs, preserving the matching scale of the paired correction dots. Keep the original zero-slab metadata scale1, even if this makes the new common scale coarser than directly inspecting the nonzero values would require. Original inputs, exact per-column inside, seven native planes and eight correction dots stay intact.

This is a new approximation: x=1.49, oldscale1, newscale2 yields RN(RN(x)/2)=0 whereasRN(x/2)=1. It must not inherit M9's pass. The controlled screen has shared native four-K128 FP32 modeled leaves and three arms: baselineK128, directly quantizedK512, and K128-to-K512 doubleRN. Sixty fresh configurations use the same ten adverse-pattern definitions asM9, new seeds5201–5203 and both dtypes. The first uniform input per dtype checks baseline and directly quantizedK512 exactly against M9's implementation on that same new input. All arms use the original already-rounded-input FP64 AB reference, fixed floors1e-4/1e-3, no nonfinite and no low saturation; exact modeled integer bound is2*512*127²=16,516,096<2²⁴. These are numerical screens, not real WGMMA, timing or synchronization acceptance.

A later hardware implementation could append an unconditional cooperative grid barrier after current packing, then let the first216of288CTAs process9planes*(8Atiles+16Btiles), requantize their four slabs in place, and repeat common exponent metadata. The extra full plane read/write is approximately9.44MB, plus exponent traffic and a second grid barrier. Existing1024column inside exponents must remain untouched. Reusing a cooperative launch does not make these costs free; all must appear in full-call timing. No global spin barrier or hidden host synchronization. One can retain the guarded fallback for unsafe restoration exponents, while expected normal inputs should have uniform exponents. Actual resident capacity still needs checking for the new producer resources.

If the model passes, hardware would be a separate isolated experiment from frozenP33, retaining every existing native/INT8 dot and current descriptor encoding. Freeze sources/binary, measure ordinary78 and exact inside exponents, and reject an already clear full-call regression before expanding validation. Any retained new hardware needs fresh seeds, both-stream Graph/direct guards and all three scoped sanitizer tools; neither M9 nor P33 certificates transfer. M10's completed screen is recorded below; P35 is the next isolated hardware control and has no measured result at this point.

These results support a hardware experiment, not hardware acceptance or a speed prediction.

P35 is generated from frozenP33. After original packing, all288CTAs execute a second unconditional grid.sync. The first72CTAs cover9planes*8Arowtiles; the next144cover9planes*16Bcolumn tiles. Because B's physical INT8 layout is transposed, both sides have contiguous K512 rows. Thread0 snapshots the four old exponents and their maximum in reused shared scratch; a block barrier completes the snapshot before byte rewrites and metadata replacement. Each plane/tile and byte has one owner; no other CTA accesses that tile's exponents in this phase. Every writer executes fence.proxy.async.global before kernel completion; the existing corrected consumer runs next on the caller's same stream. There is no final grid barrier because no CTA consumes other tiles after this phase; cross-kernel ordering and the writer proxy fences remain necessary. Native buffers, the consumer, workspace, per-column inside and descriptor encoding stay frozenP33. The conditional fallback remains for exceptional restoration exponents. Actual resource capacity and all current full preparation costs must be measured.
