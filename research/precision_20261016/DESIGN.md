# 基于消融的后续方案设计

## 约束和当前状态

主研究目标仍是七乘法 FMM 的精度与性能。用户未补充算法范围偏好时，直接输入稠密原型只作为对照，不将其称为七乘法修复，也不更改生产分发。

原始合同保持：参考为已经量化的原始 A/B 的 FP64 AB；FP16/BF16 floor 分别为1e-4/1e-3，实际验收为 `eF <= 3*eF_dense + floor`，所有 fresh trials 通过且无 nonfinite。完整调用包括输入读取、每次动态变换、尺度、量化、同步和重组。`run()` 不分配、不进行 host 同步，不缓存上次输入的计算值。

## 方案A：已验证的稠密性能对照

使用真实原始输入，FP16/BF16 WGMMA→FP32，直接计算完整 K 点积。它在数学上等价于八个原始块乘积，优化版实际采用普通64×128输出tile，不再保留显式八步块乘积调度。它不是七乘法 FMM。

- 一个 kernel，两张本次输入的 TMA map，0字节调用方workspace。
- 128 CTA，每CTA256线程；一个producer和一个128线程consumer warpgroup。
- BK128，四个operand slots，196736字节动态shared；用实际库布局产生描述符。
- 每个slot内八条k16 WGMMA，提交一组；`wait_group 1`后只释放已完成的前一个slot；最后`wait_group 0`再释放尾部。
- FP32累加器保留到完整K点积完成，直接写输出；不用S/T变换，不用跨乘积抵消。

这一对照回答“增加一次块乘法是否一定损害性能”：本轮结果是否定的。但它不回答“七乘法如何保精度”。接入现有Tuned候选属于可选后续工作；需要形状/transpose/stride/alpha/beta/对齐的精确资格判断和原有数值、确认机制，不应通过修改SW名字掩盖算法变化。

## 方案B：七乘法主路径 + 分块INT8残差信息

这是新的待实现研究候选，不能因数值模型通过就宣布性能可行。

### 数值表示

先在FP32形成S/T，主操作数为原输入dtype的 `Sh=round(S)`、`Th=round(T)`，同时保存 `Sl=S-Sh`、`Tl=T-Th`。保留七个主乘积，补偿八个标准一阶交叉项：

```
P3: Sl4 * B22
P4: A22 * Tl4
P5: Sl1 * Th1 + Sh1 * Tl1
P6: Sl2 * Th2 + Sh2 * Tl2
P7: Sl3 * Th3 + Sh3 * Tl3
```

补偿两侧均采用signed INT8，分别以本次数据的block amax选择二的幂尺度：

```
scale = 2^ceil(log2(amax / 127)), zero block -> scale=1
q = clamp(round(x / scale), -127, 127)
```

叶输出tile64×32，K128：左操作数尺度覆盖64×128，右覆盖128×32。在INT32完成每个K128点积后，按两侧尺度乘积转换并累加到FP32。`128*127^2=2064512`，不会发生该部分的INT32溢出。不同K块的尺度不同，不能直接跨块累积INT32后只缩放一次。

二阶低×低三项先作为独立消融保留可开关，而非预先断言对所有输入可忽略。常规输入上的模型支持忽略，但强消去/尺度失衡需要单独判断。

这表示七个主乘积加八个补偿乘积，绝不是“只执行七个Tensor Core乘法”。它避开FP8表示，但补偿成本依然必须实测；不能仅因INT8理论吞吐高就假定免费。

### 尺度失衡是另一个独立问题

`A`的两半K列与`B`的两半K行若互为极不均衡的尺度，变换乘积可大幅抵消。一阶补偿的相对误差也会被放大。本轮无预处理的INT8模型在六个此类输入上失败。

针对这一来源，先采用inside幂二平衡：

```
D[k] = 2^round(log2(sqrt(max_i |A[i,k]| / max_j |B[k,j]|)))
A'[:,k] = A[:,k] / D[k]
B'[k,:] = B[k,:] * D[k]
```

零行/列单独处理。参考始终是原始A/B的FP64 AB，不能将平衡后的输入重新量化后另立golden。缩放应尽量融合于本次转换，并显式处理上溢/下溢；不能把某次`tune()`得到的amax用于后续fresh输入。

该模型需要列/行reduction。**这是未解决的性能风险**。不能先测不含reduction的kernel再声称完整调用更快。极端BF16范围及FP32中间上溢仍须独立证明或验证；目前模型覆盖的动态范围不等于全部BF16值域。

数值筛选状态：无平衡时42组中36组低于固定floor，六个K方向失衡输入失败；加入inside平衡后，全部七类42组均低于固定floor，详见`int8_inside_full_model.json`。模型使用理想点积与反缩放，这个结果不是实际GPU实现的精度或性能验收。

### Hopper映射与消融顺序

1. 独立验证INT8 `m64n32k32.s32.s8.s8` 点积、布局、signedness和尺度应用，对真实量化值的FP64参考检查；这不是完整算法验收。
2. 构建只含动态inside尺度与S/T+INT8转换的producer，量出实际完整预处理时间、读写字节、shared和寄存器占用。尺度必须来自本次输入。
3. 先用研究原型融合七个主项和八个交叉项。尽量在对应叶项的片上累加器里加入缩放后的修正，避免物化八个FP32补偿输出。
4. 对比“无平衡/有平衡”“FP64理想INT8点积/真实INT32点积”“二阶项开/关”“单独补偿/融合补偿”；每次只改变一个机制。
5. 原始GPU精度全部通过后，才与当前SW和本轮6.5–6.6μs稠密对照进行完整调用交错比较。没有性能达标前不接入Auto。

重点记录：预处理完整时间、TC等operand时间、主乘法和补偿的发射/等待、INT32→FP32缩放与重组、register spill和shared约束。利用时间记录和NCU交叉解释，不把相互重叠的角色耗时直接相加。

### 接受和拒绝条件

- 精度：原始六类输入×三轮×两种dtype，以及新尺度失衡/动态范围用例，launch、Graph新输入重放、并发流均通过不变的原始门槛。
- 性能：至少三次独立进程复测，每次20warmup、5组×100调用，保持完整调用；与当前SW相比所有组不退化。若要取代强稠密对照，还需对该对照建立持续优势，而非只比旧SW。
- 若仅理想模型通过、硬件失败，先定位INT8缩放/累加/布局，不改变参考或门槛。
- 若精度通过但完整延迟退化，记录并拒绝该实现。主乘法数、理论INT8吞吐、单独量化或GEMM primitive的速度均不能代替完整调用结论。
- FP8路线仍保持停止；没有恢复旧SW架构，也不把过去的高低分量实现逐字恢复为新方案。

## 本阶段可以作出的结论

已经定位到需要修复的两个不同来源：变换cast损失与尺度失衡造成的放大。阶段消融、缩放模型、INT8表示筛选和更强的硬件对照为下一步实施提供了明确验收条件。七乘法方案的完整GPU性能尚未得到验证，因此总目标仍在进行。
